# 创想时代开发组 · 官网

这是 **Innova Age Development Team** 的官方网站源码。纯静态站点：HTML + CSS + 原生 JavaScript，
**没有框架、没有构建步骤**。改完文件直接推送到 GitHub，网站就会自动更新。

- 线上地址：**https://innovaage.cn/**
- 代码仓库：https://github.com/Porgont/innovaage-site
- 备用地址：https://porgont.github.io/innovaage-site/

> 这份文档是写给**所有参与维护的人**看的，不只是给某一个人。
> 如果你是第一次接手，从[第二节](#二30-秒上手)开始就行。

## 二、30 秒上手

### 1. 看本地效果

```bash
node tools/serve.mjs 8099
```

浏览器打开 http://localhost:8099 。
这个本地服务器会像 GitHub Pages 一样处理 404，所以能真实反映线上行为。

### 2. 改内容

95% 的日常改动只涉及两个文件：

- **`assets/js/site.js`** —— 群号、联系方式、公告、作品数据、问卷链接
- **对应的 `.html`** —— 正文文案和结构

具体怎么改，看[第四节](#四常见任务)的对应条目。

### 3. 自检（养成习惯，别跳过）

```bash
node tools/check.mjs          # 结构与链接检查，几秒出结果
node tools/browser-test.mjs   # 真浏览器跑行为测试（需先起 serve.mjs）
```

两个都显示「全部通过 / 0 项失败」再提交。

### 4. 发布

```bash
git add .
git commit -m "一句话说明改了什么"
git push
```

推完等 1～2 分钟自动生效。

## 四、常见任务

### 4.1 发一条公告（零基础照着做）

这条写给宣传部：**只改一个文件**，不用懂编程。

#### 第一步：打开对的文件

用 VS Code（或任何文本编辑器）打开：

```
assets/js/site.js
```

在文件里搜索 `ANNOUNCEMENTS`，会看到这样一段：

```js
var ANNOUNCEMENTS = [
  {
    id: 'subdomain-open',
    date: '2026-10-17',
    ...
  },
  ...
];
```

#### 第二步：复制一条当模板

把 `[` 后面**整条**（从 `{` 到 `},`）复制一份，粘在最前面，然后改里面的内容。

新公告**放最前面**，日期相同时它就会排在前面。

#### 第三步：逐项填

| 字段 | 填什么 | 例子 |
|---|---|---|
| `id` | 网址里用的英文编号，**只能小写字母、数字、短横线**，不能和别人重复 | `'new-version-2027'` |
| `date` | 日期，格式固定 `年-月-日`，**月、日不足两位要补 0** | `'2027-03-05'` |
| `title` | 标题，一句话，别太长 | `'「丹青渡」版本更新说明'` |
| `color` | 左边那根色条，四选一 | `'green'` / `'gold'` / `'diamond'` / `'redstone'` |
| `pin` | 要不要置顶，不置顶就**整行删掉** | `true` |
| `tags` | 标签，决定公告页的筛选按钮能不能筛到它。常用：`'招募'`、`'版本发布'`、`'合作'`、`'站点'`、`'里程碑'` | `['版本发布']` |
| `body` | 正文，写法见下一节 | `'<p>……</p>'` |

#### 第四步：写正文

正文用 **Markdown** 写，就是平时在 QQ、微信里打字再加几个符号。整段用一个反引号字符串包起来：

```js
body: `
这里是一段普通文字，直接写就行。

第二段和第一段之间空一行。

## 这是一个小标题

**这句话要加粗**，用两个星号包住。

- 列表第一条
- 列表第二条

要放链接：[点这里打开](https://docs.qq.com/doc/xxxx)
`
```

常用的几个写法：

| 想做什么 | 怎么写 |
|---|---|
| 分段 | 中间**空一行** |
| 加粗 | `**这句话**` |
| 小标题 | `## 标题` |
| 列表 | 每行开头写 `- `（短横线加空格） |
| 放链接 | `[显示的字](网址)` |
| 放图片 | `![图片说明](assets/img/文件名.jpg)` |
| 引用 / 强调块 | 每行开头写 `>` 加空格 |
| 行内代码 | 用反引号包住，如 `组件码 8144171` |

要点：

- **前后各用一对反引号把整段包起来**（键盘左上角、Esc 下面那个键），不要用单引号
- 反引号包起来的字符串里，**可以随便换行**，不用写加号拼接
- 如果非要用单引号写法，那正文里**不能出现英文单引号**，会报错；用 Markdown 就绕开了这个坑
- 想插空行又觉得间距不够：空两行

#### 第五步：放图片

1. 把图片放进 `assets/img/` 文件夹
2. 文件名用**英文小写 + 短横线**，不要中文、不要空格
   好：`news-2027-banner.jpg` ／ 不好：`公告图 1.png`
3. 图片宽 1200 像素左右就够了，**单张控制在 500KB 以内**
4. 在正文里这样引用：

```
![这张图画了什么](assets/img/news-2027-banner.jpg)
```

方括号里写一句这图画了什么，方便别人看不清图时也能懂。图片会占满正文宽度，不用自己调大小。

#### 第六步：看效果

在项目文件夹里开一个终端，运行：

```
node tools/serve.mjs 8099
```

然后浏览器打开 `http://127.0.0.1:8099/news.html`，就能看到你写的公告。

#### 第七步：发布

改完跑一下自检，绿了再提交：

```
node tools/check.mjs
git add -A
git commit -m "新增公告：标题"
git push
```

等 1 分钟左右，`https://innovaage.cn/news.html` 上就有了。

#### 公告列表上显示的那一小段是自动截的

公告列表**只显示标题 + 正文开头约 96 个字**，点进去才是全文。所以：

- 正文**第一句就要说清这件事**，它会成为列表上的摘要
- 别把「两件事一起说：」这种空话放在最开头，列表上会很难看

#### 第六步：更新 RSS

公告页有个 `feed.xml`，订阅的人靠它收更新。**加完公告跑一次**：

```bash
node tools/build-feed.mjs
```

它会读 `site.js` 里的公告数据，重新生成 `feed.xml`。不跑的话，网站上是新的，RSS 里还是旧的。

#### 字体：改完文案跑一次

全站用的是 **HarmonyOS Sans SC**，而且只保留了站内**用得到的那些字**（子集化，372 KB）。

出现以前没出现过的字时，那个字会回退成系统字体，看起来会比旁边粗一点、字形也不一样。
改完文案跑一次：

```bash
node tools/subset-font.mjs
```

会重新扫一遍所有页面，把新字补进字体文件。具体说明见 `assets/fonts/README.md`。

#### 常见错误

| 现象 | 原因 |
|---|---|
| 页面全白、公告不显示 | 少了一个 `,`；或者正文那对反引号没配对。按 F12 看 Console 的红色报错 |
| 日期显示成 03/5 而不是 03/05 | `date` 里月/日没补 0 |
| 公告页筛选筛不到 | `tags` 里没写对应标签 |
| 图片是破图 | 路径写错，或文件没放进 `assets/img/` |
| 网址打开是「没找到这篇公告」 | `id` 重复了，或者复制时漏了 |

### 4.2 加一件代表作品（零基础照着做）

加作品也是**只改一个文件**：`assets/js/site.js`。有两处要加。

#### 第一步：准备图

1. 图片放 `assets/img/`，文件名英文小写 + 短横线，例如 `wuming-1.jpg`
2. 封面图**宽 1200 像素左右**就够，别直接丢 4000 像素的原图
3. **单张控制在 600KB 以内**（超过就拿系统自带的「画图」或在线工具压一下）
4. 同一件作品可以有多张截图，命名 `作品名-1.jpg`、`作品名-2.jpg`

#### 第二步：在 `SHOWCASE` 里加一条（列表卡片）

搜索 `var SHOWCASE = [`，在数组里加：

```js
{
  id: 'wuming',                          // 英文小写，和下面 WORKS 里的编号一致
  img: 'assets/img/wuming-1.jpg',        // 列表里显示的封面
  title: '无名',                          // 作品名
  meta: '作者：某某',                     // 作者行，写真人
  category: 'shader',                    // 见下表
  desc: '一句话说明这件作品是什么。'
},
```

`category` 只能填下面五个之一，它决定卡片上那个小标签显示什么：

| 填什么 | 显示 |
|---|---|
| `shader` | 光影 |
| `map` | 地图 |
| `skin` | 皮肤 |
| `tex` | 材质 |
| `addon` | Addon |

#### 第三步：在 `WORKS` 里加一条（详情页）

搜索 `var WORKS = {`，加一项。**键名必须和上面的 `id` 完全一样**：

```js
'wuming': {
  name: '无名',
  author: '某某',
  type: '光影 / Shader',
  tagline: '一句话定位，显示在标题下面',
  cover: 'assets/img/wuming-1.jpg',
  coverAlt: '封面图里画了什么',
  facts: [                               // 右侧信息栏，想写几行写几行
    { k: '作品名', v: '无名' },
    { k: '作者', v: '某某' },
    { k: '类型', v: '光影 / Shader' },
    { k: '平台', v: 'Minecraft 基岩版' }
  ],
  intro: [                               // 正文，一个字符串一段
    '第一段介绍。',
    '第二段介绍。'
  ],
  shots: [                               // 详情页截图，想放几张放几张
    { img: 'assets/img/wuming-1.jpg', alt: '这张图展示了什么' },
    { img: 'assets/img/wuming-2.jpg', alt: '这张图展示了什么' }
  ]
},
```

`shots` 里**只写 `img` 和 `alt`**，不写说明文字 —— 详情页不显示说明，说明只给屏幕阅读器和搜索引擎看。

#### 想放「获取地址 / 下载链接」？

**别在正文里写超链接**，用 `links` 字段做成按钮：

```js
links: [
  {
    title: '网易版',
    items: [
      { label: '四合一', href: 'https://...' },
      { label: '普通版 128x', href: 'https://...' }
    ]
  },
  {
    title: 'Java 版',
    items: [{ label: '爱发电', href: 'https://...' }]
  }
],
```

每组一个 `title`，`items` 里每个按钮一行。渲染出来是描边按钮，点开在新窗口打开。

#### 只想挂着展示、不做详情页？

那就**只在 `SHOWCASE` 里加一条，不要填 `id`**。这样卡片上不会出现「查看详情 →」。

#### 规则（自检会盯着）

- **一个作品只能占 `SHOWCASE` 的一条**。多张图放进 `WORKS` 的 `shots`，别在 `SHOWCASE` 里重复列
- **作者写真人，不要写「创想时代开发组」**。团队只能作为「移植与维护」之类的角色出现在 `facts` 里
- 不知道的信息就**不写**（比如不确定是基岩版还是 Java，就别填 `平台`），不要猜

#### 第四步：看效果、发布

```
node tools/serve.mjs 8099
```

打开 `http://127.0.0.1:8099/works.html` 看列表，点进详情页再看一遍。

确认没问题：

```
node tools/check.mjs
git add -A
git commit -m "新增作品：无名"
git push
```

#### 作品主页的作品：不要写 `shots`

放进 `SHOWCASE_HOME`（作品主页那一栏）的作品，**不列单独的截图区**。
详情页的那一栏会自动隐藏（代码里写死了，不靠数据里记得清空）。

图片直接插在正文里，按位置排：

```js
intro: [
  '一段说明文字',
  { heading: '某一版' },
  { imgs: [
      { img: 'assets/img/x-1.jpg', alt: '这张画了什么' },
      { img: 'assets/img/x-2.jpg', alt: '这张画了什么' }
  ] },
  { links: [{ items: [{ label: '下载', href: 'https://...' }] }] }
]
```

能用四种块：普通字符串（一段正文）、`{ heading }`（小标题）、`{ imgs }`（三张并排的图）、`{ links }`（按钮组）。
想插图就插在对应的位置，**不要另外写 `shots`**。

#### 想放到「测试中作品」而不是代表作品？

在 `SHOWCASE` **下面**有个 `var SHOWCASE_TEST = [];`，把条目放进那个数组，字段完全一样。
它会出现在作品页的「尚未正式发布的测试组件」栏和首页的「测试中作品」栏，不占代表作品的位置。

#### 常见错误

| 现象 | 原因 |
|---|---|
| 卡片有了但点进去是别人的内容 | `WORKS` 里的键名和 `SHOWCASE` 的 `id` 对不上 |
| 卡片上没有「查看详情」 | `SHOWCASE` 那条忘了写 `id` |
| 图片破图 | 路径写错，或文件没放进 `assets/img/` |
| 同一件作品出现好几次 | 在 `SHOWCASE` 里重复列了，应该合并成一条 |
| 页面白屏 | 少逗号、少引号；按 F12 看 Console |

### 4.3 改联系方式 / 群号

只改 `assets/js/site.js` 顶部的 `SITE_CONFIG`，全站（页脚、联系页、关于我们）一起生效。

```js
var SITE_CONFIG = {
  surveyUrl: 'https://www.wjx.cn/vm/xxxx.aspx',  // 报名问卷（问卷星）
  qqAudit:   '1045216325',   // 对外审核群
  qqPublic:  '788233856',    // 对外交流群
  qqCouncil: '1018260006',   // 开发理事会（对外代投）

  neteaseMc:    '创想时代开发组',   // 网易我的世界
  neteaseHd:    '创想时代工作室',   // 网易大神
  douyin:       '创想时代开发组',   // 抖音
  bilibiliName: '创想时代开发组',   // B 站显示名
  bilibili:     'https://space.bilibili.com/488348167',  // B 站主页

  email: '',      // 留空 = 自动隐藏这一行
  discord: '',    // 留空 = 自动隐藏这一行
  ...
};
```

**留空的联系方式会自动隐藏整行**，不会留下空行或「待填写」占位。

页面上用的是 `data-fill` / `data-fill-href` 两个属性做占位：

- `data-fill="键名"` → 这个元素的**显示文字**取 `SITE_CONFIG[键名]`
- `data-fill-href="键名"` → 这个元素的**跳转链接**取 `SITE_CONFIG[键名]`

两者可以指向不同的键。例如 B 站那行：文字用 `bilibiliName`（账号名），链接用 `bilibili`（主页地址）。

### 4.4 加图片

图片放 `assets/img/`，然后按 4.2 或 4.3 引用。

**图片规范**（请不要破坏，直接影响加载速度）：

- 文件名英文小写 + 短横线，例如 `shader-rain.jpg`
- **单张压到 500KB 以内**
- 横构图建议 16:9 或 3:2
- 详细要求见 `assets/img/README.md`

MC 截图常常有 2–5MB，需要先压缩。压图可以：用站内的[图片处理工具](https://innovaage.cn/tools-image.html)，
或 `node tools/process-shader-images.mjs`。

> 图片工具的预设里有个 **「无限制」**：选了它就不动像素尺寸，只按「输出格式」重新编码
> （比如 PNG → JPG 压体积）。要单纯转格式、不改分辨率时用这一档。

### 4.5 换首页大图

改 `SITE_CONFIG` 里这两行：

```js
heroImage: 'assets/img/你的图.jpg',
heroImageAlt: '图片内容描述'
```

**留空 `heroImage` 则首页大图整块自动隐藏**，布局自动变成单列，不会留下空框。

### 4.6 加一个新工具

工具箱现在是「入口页 + 每工具一页」的结构：

1. 复制 `tools-image.html` 另存为 `tools-new.html`
2. 改标题、描述、`<main>` 里的工具本体
3. 新工具的逻辑单独放 `assets/js/your-tool.js`，在页面底部引入
4. 在 `tools.html` 的 `.module-grid` 里加一张卡片指过去

### 4.7 改配色

全部颜色在 `assets/css/theme.css`，分四段，优先级从低到高：

```css
:root { }                                 /* 1. 默认：浅色 */
@media (prefers-color-scheme: dark) { }   /* 2. 系统偏好深色时 */
html[data-theme="light"] { }              /* 3. 访客手动选浅色 */
html[data-theme="dark"]  { }              /* 4. 访客手动选深色 */
```

改强调色只动第 1 段的 `--gold`，另外三段同步一下。

> ⚠️ **新增主题变量时四段都要加**，否则某种模式下会是空值。
> `node tools/check.mjs` 会自动比对并报错，不用自己数。

## 六、自检与发布

### 自检脚本

```bash
node tools/check.mjs             # 文件、链接、id、语法、CSS 括号、主题变量完整性
node tools/verify-structure.mjs  # 页眉、手机侧栏、各分区是否完整
node tools/browser-test.mjs      # 浏览器行为（需先起 serve.mjs）
node tools/test-video.mjs        # 视频工具主流程（需先起 serve.mjs）
node tools/test-video-repeat.mjs # 视频工具连续转换（各起一个独立浏览器）
```

这几个脚本**不需要 npm 依赖**，装了 Node 就能跑。

> 如果改了群号、问卷链接或作品数量，记得同步改测试里的断言，
> 否则会出现「测试失败但页面其实是对的」。

> **为什么要拆成三个浏览器测试**：视频录制会占用浏览器的媒体管线，
> 而且额度是按**浏览器进程**算的 —— 一个进程里大约连续录 3 次之后，
> `MediaRecorder` 会启动但产不出任何数据（无头 + 纯软件编码下尤其明显）。
> 所以要拆开：`browser-test.mjs` 只查页面不录像，
> `test-video.mjs` 在一个新浏览器里只录 1 次，
> `test-video-repeat.mjs` 在另一个新浏览器里录 2 次验证连续转换。
> 混在一起跑会把「环境还剩多少额度」误判成工具故障。

页面上如果真的遇到这个额度用尽，工具会明确提示**按 F5 刷新页面**，
不是死路。

## 七、多人协作约定

这个仓库会有多位高管一起改，为了避免互相踩：

1. **改之前先 `git pull`。** 直接改本地旧版本再推，会覆盖别人的改动。
2. **一次提交只做一件事。** 「加了一条公告」和「顺手改了样式」分开提交，
   出问题时好回滚。
3. **改完先跑自检再推。** 推上去之后线上是坏的，所有人都看得见。
4. **别动 `CNAME` 和 `.nojekyll`。** 删了自定义域名会掉、Pages 处理也会变。
5. **改了别人的内容先说一声。** 尤其是公告、领导名单、联系方式这类对外信息。
6. **拿不准就问。** 这个站没有构建步骤，改错了回滚也很容易：
   `git log` 找到上一次好的提交，`git revert` 或 `git checkout -- 文件名` 即可。

### 冲突了怎么办

```bash
git pull            # 拉最新
# 如果有冲突，Git 会在文件里标出 <<<<<<< 和 >>>>>>>
# 手工改成你想要的样子，删掉这些标记
git add .
git commit -m "解决冲突"
git push
```

不改代码、只是看看线上效果：直接开 https://innovaage.cn/ 。

## 八、已完成的配置（备查）

这些是一次性配好的，平时不用动。写在这里是因为万一出问题要知道去哪查。

### GitHub Pages

仓库 → Settings → Pages：

- Source: `Deploy from a branch`
- Branch: `main`，目录 `/ (root)`
- Custom domain: `innovaage.cn`（靠仓库里的 `CNAME` 文件）
- Enforce HTTPS：**已勾选** —— `http://` 会自动 301 跳到 `https://`

### DNS（阿里云）

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | `185.199.108.153` | 600 |
| A | `@` | `185.199.109.153` | 600 |
| A | `@` | `185.199.110.153` | 600 |
| A | `@` | `185.199.111.153` | 600 |
| CNAME | `www` | `porgont.github.io` | 600 |

根域名必须用 A 记录（DNS 规范不允许根域名用 CNAME），四条都要加，缺一条会有部分访客打不开。

> ⚠️ **不要动 MX 和 SPF 记录**，如果这个域名在教育邮箱，动了邮件就废了。

### HTTPS

**已经能用了**。`https://innovaage.cn/` 证书有效，`http://` 会自动 301 跳转过去。

GitHub 会自动续签证书，平时不用管。**如果哪天网站又提示「不安全」**，先按这个顺序查：

1. 连 `innovaage.cn:443` 看证书主题是不是 `CN=innovaage.cn`；
   如果变回 `CN=*.github.io`，说明证书掉了（自动续签失败）
2. 到 GitHub 仓库 → Settings → Pages 看一眼：`Enforce HTTPS` 是否被自动取消
3. 修的办法：把 Custom domain 里的 `innovaage.cn` **删掉再填一遍** → Save，
   等 GitHub 重新签发（通常几分钟到 24 小时），签好后重新勾 Enforce HTTPS

> 排查记录（2026-10）：当初证书一直没签下来，`Enforce HTTPS` 的勾选框是灰的，
> 提示 `your domain is not properly configured to support HTTPS`。
> 当时 DNS 的 `✓ DNS check successful` 是正常的，卡住的只是签发这一步，**GitHub 后来自己签完了**，
> 不需要删域名重加。以后遇到灰框，先等一等再刷新设置页，别急着改配置。

### 国内访问速度

GitHub Pages 服务器在海外，国内访问时快时慢，这是线路问题不是配置问题。
域名解析到海外服务器不需要 ICP 备案；但**以后如果换到国内服务器，就必须先备案**。

## 九、技术说明

- **零构建**：写完直接推，GitHub Pages 直接托管源文件。没有打包、没有编译。
- **主题记忆**：访客手动切换过深浅色后记在 `localStorage` 的 `ia-theme`；
  没手动选过就跟随系统。每个页面 `<head>` 里有一小段内联脚本防止刷新时闪屏。
- **手机端侧栏**：纯 CSS 实现（隐藏 checkbox + label），零 JS。
  这段标记**必须放在 `</header>` 之后** —— 页眉带 `backdrop-filter`，
  会成为 `position: fixed` 子元素的包含块，放进去侧栏就铺不满屏幕了。
- **视频工具**：浏览器里没有直接转码的 API，所以是「一边播一边录」——
  画面画到 canvas 上，用 `MediaRecorder` 录成 MP4。代价是耗时约等于视频时长。
  编码检测用自托管的 `mp4box.js`（`assets/vendor/`），不依赖外网 CDN。
- **第三方库**：目前只有 `mp4box.js`（读 MP4 编码信息用）。
