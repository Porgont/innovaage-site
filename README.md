# 创想时代开发组 · 官网

这是官网的源代码。改完文件推送到 GitHub，网站 1～2 分钟后自动更新。

- 线上地址：**https://innovaage.cn/**
- 代码仓库：https://github.com/Porgont/innovaage-site

> 这份文档给所有要改网站的人看。**不懂代码也能照着做**，
> 最常用的三种活（改文字、发公告、加作品）都写了完整例子，照抄改字就行。

---

## 一、先弄明白三件事

**第一件：网站就是一堆文件。**
每个页面是一个 `.html` 文件，图片放在 `assets/img/` 里，文字和作品信息大部分存在
`assets/js/site.js` 里。改网站就是改这些文件，跟改 Word 文档没本质区别。

**第二件：改完要「推」上去。**
你在自己电脑上改的是副本（叫本地），改完推一下，GitHub 上那份才更新，网站才跟着变。
不推，谁也看不到。

**第三件：改坏了能退回来。**
每次推之前，Git 都会存一个快照。真改坏了，退回到上一个快照就行，不会丢东西。

## 二、第一次准备（只做一次）

需要三个软件，都是免费的：

| 软件 | 干什么用 | 下载 |
|---|---|---|
| **VS Code** | 打开和编辑文件，还能看效果 | https://code.visualstudio.com/ |
| **Git** | 把改动推上去 | https://git-scm.com/download/win |
| **Node.js** | 跑「本地预览」和「自检」这两类小工具 | https://nodejs.org/ （选 LTS 版） |

装的时候一路点「下一步」就行，不用改选项。

> 完全没碰过这些软件的话，**找技术部帮你装一次、把仓库拉下来一次**，之后你就能自己改文字了。

### 把仓库拉到电脑上

1. 在你想放项目的地方新建文件夹，比如 `D:\网站`
2. 在该文件夹里右键 →「在终端中打开」（或者在地址栏输入 `cmd` 回车）
3. 粘贴下面这行，回车，等它跑完：

```bash
git clone https://github.com/Porgont/innovaage-site.git
```

4. 会多出一个 `innovaage-site` 文件夹，这就是项目
5. 用 VS Code 打开它：VS Code 菜单「文件 → 打开文件夹」，选这个文件夹

### 看一眼本地效果

1. VS Code 菜单「终端 → 新建终端」
2. 输入：

```bash
node tools/serve.mjs 8099
```

3. 浏览器地址栏输入 `http://127.0.0.1:8099` 回车

本地看到的和线上的长得一样。这个终端窗口别关，关了本地预览就停了。
改完文件保存，回到浏览器按 F5 刷新就能看到新内容。

## 三、最常见的几件事（挑你要做的看）

> 只想发公告、发代表作品：**直接看 3.0**，用网页后台，不用装东西。
> 要改版式、加专题页、改作品详情：看 3.1 之后的几节。

### 3.0 用网页后台发内容（宣传部最常用，不用装任何东西）

公告和代表作品都有网页表单，浏览器登录就能改，**不用碰代码、不用装软件**。
这一节是完整教程，照着做就行；想改文件也可以，见 3.2 的 B 和 3.3 的 B。

**表单里的灰字说明就是使用说明书**：每个字段下面都写了这一栏填什么、有没有格式要求，
正文那栏还写了加粗 / 小标题 / 列表 / 插图怎么点，并给了可以直接套的正文模板。
「标识」填错格式会当场标红提示，不会让你存进去一个坏链接。

#### 一次性准备（只有仓库所有者做一次）

1. 浏览器打开 <https://app.pagescms.org>，点「Sign in with GitHub」
2. 第一次会要求授权这个仓库：按提示允许，仓库选 `Porgont/innovaage-site`，分支 `main`
3. 授权完，左侧会出现两个栏目：**公告**、**代表作品**

给同事开权限（二选一，效果一样）：

- 在 CMS 左侧点 `Collaborators`，输入同事的 GitHub 邮箱或用户名邀请
- 或在 GitHub 仓库 → `Settings` → `Collaborators` → `Add people`

对方同意邀请后，用同一个网址登录、选仓库，就能开始发内容了。

> 没有写权限的人只能看、不能保存。这一步是 GitHub 的权限，不是网站的问题。

#### 日常发一条公告

```
打开 app.pagescms.org → 左边「公告」→ 点「Add an item」
   ↓
填表 → 右上角 Save
   ↓
等 1 分钟左右，刷新官网 news.html 就能看到
```

保存时 CMS 会自动往仓库提交一次，GitHub Pages 接着重新构建，通常 1 分钟内生效。

#### 公告表单每一项怎么填

| 表单字段 | 填什么 | 例子 |
|---|---|---|
| 标识 | 网址里用的编号，**英文小写、数字、短横线**，不能和别人重复 | `new-year-2027` |
| 日期 | 点一下选日期即可 | `2027-01-20` |
| 标题 | 一句话说清这条是什么 | `新年第一波材质包上架` |
| 卡片颜色 | 四选一，颜色只影响列表左边那根竖条 | 金（站点动态）/ 钻（制度规则）/ 绿（招募活动）/ 红石（里程碑） |
| 标签 | 筛选用，多个用**英文逗号**隔开 | `招募,代投` |
| 置顶 | 想让它一直排在最前面就打开 | 通用公告建议关掉 |
| 正文 | 富文本编辑器，能加粗、加小标题、列清单、插图 | 见下 |

**正文怎么写**（和 Word 差不多）：

- 想加粗：选中文字 → 点工具栏 **B**
- 想加小标题：选中文字 → 选「标题 2」
- 想加列表：点工具栏的列表按钮
- 想放链接：选中文字 → 点链接按钮 → 粘贴网址
- 想放图：点插图按钮 → 上传（会存进 `assets/img/`）→ 图片自动插入
- 右边有个「预览 / 源码」开关，会 Markdown 的人可以直接写源码

**第一句要直接说事**：公告列表只显示正文开头约 96 个字，别一上来写「今天说几件事」。

#### 代表作品表单每一项怎么填

| 表单字段 | 填什么 | 例子 |
|---|---|---|
| 标识 | 英文小写、唯一。**有详情页的必须和详情页的 id 一样** | `wuming` |
| 作品名 | 卡片上的大字标题 | `无名` |
| 封面图 | 横图，点一下上传 | `assets/img/wuming-1.jpg` |
| 类型 | 五选一：光影 / 地图 / 皮肤 / 材质 / Addon | 光影 |
| 作者与署名 | 写真人名，不要只写开发组 | `作者：创想时代 Log_坤` |
| 一句话简介 | 卡片上那句话，**不写句号** | `基岩版光影，主打水面反射` |

点开一条后，上面前 6 项是**卡片**（作品页与首页看到的那一格）。
下面还有一个 **「详情页」折叠组**，展开就是点「查看详情」进去那一页的内容，全部可选填，不填也能保存。
**详情页那三栏都是纯文字，一行一条**：

```
右栏信息栏            截图                          鸣谢
作品名 | 企业·灰色幽灵   assets/img/x-1.jpg | 主界面 | 基岩版   测试 | 某某
作者 | 创想时代 Log_坤   assets/img/x-2.jpg | 细节 | 基岩版     素材 | 某某
类型 | 皮肤 / Skin      assets/img/x-3.jpg | 光影 | Java 版
```

**每个字段下面那段灰字就是教程**，写正文那栏里还带一份可以直接套的模板。

| 表单字段 | 填什么 | 例子 |
|---|---|---|
| 详情页作者 | 详情页顶部那行「作者：」 | `创想时代 Log_坤` |
| 详情页类型行 | 标题上面那行分类 | `光影 / Shader` |
| 详情页副标题 | 标题下面那句定位 | `基岩版光影，主打水面镜面反射` |
| 详情页大图 | 不填就用上面的封面图 | — |
| 大图说明 | 不显示，只给读屏和搜索用 | `晴天樱花树下的草地与花簇` |
| 右栏信息栏 | 每行一项，例如 作者 / 类型 / 平台；**不确定的别写** | `作者` → `Log_坤` |
| 正文 | Markdown：空行分段、`## 小标题`、`- 列表`、`![](图片)` 插图 | — |
| 截图 | 页面底部那一组，点开可放大；可填分组名按版本分组 | — |
| 海报 / 海报说明 | 可选，正文最前面的大图 | — |
| 使用须知 | 可选，红色提示条 | — |
| 鸣谢 | 可选，每行一项 | — |

**调顺序**：每条左边有个把手，按住往上拖，越靠上越靠前。首页与作品页都按这个顺序排。

**封面图要求**：宽度 1200～1400 像素够用，**单张压到 500KB 以内**（用站内 [图片处理工具](https://innovaage.cn/tools-image.html) 压）。
文件名用英文小写加短横线，别用中文和空格。

> 「专题页」和「测试中作品」的详情**不在这里**，它们各有排版，仍然写在 `site.js` 里，见 3.4。

#### 保存之后会发生什么

1. CMS 往仓库提交一次（提交信息里能看到你改了什么）
2. GitHub Pages 自动重新构建，通常 **1 分钟内**官网就更新
3. 想看有没有生效：强刷 `Ctrl + F5`，或者打开 `news.html` 看列表

RSS 订阅文件 `feed.xml` **不会**自动跟着变。要更新它，找会跑命令的人执行一次：

```bash
node tools/build-feed.mjs
```

#### 这些内容不能在这里改

| 想改的东西 | 去哪改 |
|---|---|
| 公告、代表作品卡片 | 就在网页后台（本节） |
| 页面上的固定文字（例如关于我们里的介绍） | 3.1，改 `.html` |
| 专题页正文（无人区跑酷、仿真工艺） | 就在网页后台「专题页」栏目里改，排版固定（见 3.4） |
| 梦海旅者、创想之都 | 独立小站，各有页面，见 3.4 |
| 首页那四条专题页横幅 | 3.4，改 `site.js` |
| 测试中作品 | 也在 `site.js`，按 3.4 的写法 |

专题页不做成同一个模板，是刻意的安排。

#### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开网址提示要授权 | 第一次用，或换了账号 | 点授权，仓库选 `Porgont/innovaage-site` |
| 左侧一片空白 / 提示没有配置 | 分支不是 `main`，或者仓库选错了 | 左上角把分支切到 `main` |
| 能填但保存报错 | 账号没有仓库写权限 | 让管理员在 GitHub 里邀请你，接受邀请后再试 |
| 保存成功但官网没变 | GitHub Pages 还在构建 | 等 1～2 分钟强刷；超过 5 分钟告诉管理员 |
| 图片不显示 | 图太大没传完，或文件名有中文空格 | 压到 500KB 以内，改成英文小写加短横线 |
| 日期显示不对 | 以前手写日期漏了补 0 | 用日期选择器选，别手打 |
| 列表顺序不对 | 公告按「置顶 + 日期」自动排，不看拖动顺序 | 想靠前就把日期改新，或打开置顶 |
| 误删了一条 | 保存后立刻发现 | 在 GitHub 该文件的历史里恢复，或告诉管理员 |

### 3.1 改一段已有的文字

比如想把「关于我们」里那句下载量改掉。

1. VS Code 里按 `Ctrl + P`，输入 `about.html`，回车打开
2. 按 `Ctrl + F` 搜索你想改的原句，比如 `五千万`
3. 直接改这几个字，改完按 `Ctrl + S` 保存
4. 浏览器刷新看效果
5. 按第四节的步骤推上去

**只改文字是可以放心的**：不要动尖括号 `< >` 里面的东西，那就是排版标记。
把它们想成「格式开关」，删了页面就乱。

```
改前：<p>在我的世界中国版总下载量已超过五千万。</p>
改后：<p>在我的世界中国版总下载量已超过六千万。</p>
      ↑ 这些尖括号里的内容别动，只改中间的中文
```

### 3.2 发一条公告

公告**已经不在代码里了**，现在放在 `content/announcements.json`。有两种改法，挑一种。

#### A. 用网页表单

完整教程在 **3.0**，这里不重复。一句话版本：打开 <https://app.pagescms.org> →
左边「公告」→ 新增 → 填完点 Save → 等 1 分钟。

#### B. 直接改文件（会一点电脑操作用这个）

打开 `content/announcements.json`，往列表最前面加一条：

```json
{
  "announcements": [
    {
      "id": "new-2027-01",
      "date": "2027-01-20",
      "title": "新年第一波材质包上架",
      "color": "gold",
      "tags": ["版本发布"],
      "pin": false,
      "body": "第一句先写清楚这是什么。\n\n## 小标题这样写\n\n正文一段一行，**想加粗用两个星号**。"
    }
  ]
}
```

三条铁律：

- 每条之间用**英文逗号** `,` 分开，最后一条后面不加逗号
- 正文里的换行写成 `\n\n`（反斜杠 + n，两个字符）
- 引号一律用英文双引号 `"`，别用中文引号

#### 每一项填什么

| 写什么 | 意思 | 例子 |
|---|---|---|
| `id` | 网址里用的编号，**小写英文、数字、短横线**，不能重复 | `"new-2027-01"` |
| `date` | 日期，固定「年-月-日」，**月日不足两位补 0** | `"2027-01-20"` |
| `title` | 标题，一句话 | `"新年第一波材质包上架"` |
| `color` | 左边那根色条，四选一 | `"green"` `"gold"` `"diamond"` `"redstone"` |
| `pin` | 想置顶写 `true`，不置顶写 `false` | `true` |
| `tags` | 标签，决定筛选按钮能不能筛到它 | `["招募"]` `["版本发布"]` `["合作"]` |
| `body` | 正文，用下面这套写法 | 见上例 |

#### 正文怎么写

正文用的是 **Markdown**，就是打字时多加几个符号：

| 想做什么 | 怎么写 | 效果 |
|---|---|---|
| 分段 | 中间空一行（在 JSON 里写 `\n\n`） | 两段分开 |
| 加粗 | `**这几个字**` | **这几个字** |
| 小标题 | `## 标题文字` | 大一号的标题 |
| 列表 | 每行开头写 `-` 加空格 | • 一条 |
| 放链接 | `[显示的字](网址)` | 显示的字可点 |
| 放图片 | `![图里画了什么](assets/img/xx.jpg)` | 图片 |

**加粗有个坑**：`**加粗文字**` 后面如果**直接紧跟中文**（中间没有标点或空格），
星号会被当成普通文字显示出来。两种写法都行：

- 把标点放在星号外面：`**申请方式**：到……`
- 或者直接写 HTML：`<strong>申请方式：</strong>到……`

用网页表单（A 方式）的话，这两条不用你自己写，点工具栏的「加粗」就行。

#### 放图片

1. 图片丢进 `assets/img/` 文件夹（网页表单可以直接上传，会存到这里）
2. 文件名用**英文小写加短横线**：`news-2027-banner.jpg` ✔ ／ `公告图 1.png` ✘
3. 宽度 1200 像素够用，**单张压到 500KB 以内**（用站内 [图片处理工具](https://innovaage.cn/tools-image.html) 压）
4. 正文里这样写：`![新年活动海报](assets/img/news-2027-banner.jpg)`

#### 保存之后

- 公告列表**只显示标题和正文开头约 96 个字**，所以正文第一句要直接说清是什么事
- 用网页表单保存的，等 1 分钟刷新官网就能看到
- 直接改文件的，本地跑 `node tools/check.mjs` 看最后一行是不是「全部检查通过」，再按第四节发布
- 想让 RSS 订阅者也收到，跑一次 `node tools/build-feed.mjs`
- 新出现的汉字会先用系统字体顶上，不影响阅读；想和全站字体完全一致再跑 `node tools/subset-font.mjs`

#### 出现这些情况怎么办

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 公告一条都不显示 | JSON 写坏了（逗号、引号、少半个括号） | 用 VS Code 打开会标红；或按 F12 看 Console |
| 列表上日期显示成 01/2 | `date` 里月日没补 0 | 改成 `"2027-01-02"` |
| 点进公告说「没找到」 | `id` 重复了 | 换个没用过的编号 |
| 筛选按不到它 | `tags` 里没写对应标签 | 补上 `"版本发布"` 这类 |
| 图片是破图 | 路径写错，或没放进 `assets/img/` | 对照文件名逐个字母检查 |
| 换行没生效 | 写成了真的空行，或者只写了一个 `\n` | 改成 `\n\n` |

### 3.3 加一件代表作品

代表作品的两层都在 `content/works.json` 里：

- **卡片**：封面、名字、类型、作者、一句话简介
- **详情页**：大图、右栏信息、正文、截图、海报、须知、鸣谢

#### A. 用网页表单（卡片与详情都能改）

完整教程在 **3.0**。一句话版本：打开 <https://app.pagescms.org> → 左边「代表作品」→
新增或展开一条 → 上半部分填卡片，下半部分填详情 → Save → 拖动把手调顺序。

展开一条后会看到两个部分：上面是卡片（6 项），下面是「详情页」折叠组（作者、类型行、副标题、大图、信息栏、正文、截图、海报、须知、鸣谢）。
填了详情组，点「查看详情」就有完整页面；只填卡片也能保存，只是详情页会缺内容。

#### B. 直接改文件

打开 `content/works.json`，往 `works` 列表里加一条：

```json
{
  "id": "wuming",
  "title": "无名",
  "img": "assets/img/wuming-1.jpg",
  "category": "shader",
  "meta": "作者：某某",
  "desc": "一句话说明这是什么",

  "author": "某某",
  "type": "光影 / Shader",
  "tagline": "一句话定位，显示在标题下面",
  "cover": "assets/img/wuming-1.jpg",
  "coverAlt": "封面图里画了什么",
  "facts": [
    { "k": "作品名", "v": "无名" },
    { "k": "作者", "v": "某某" }
  ],
  "body": "第一段介绍。\n\n## 小标题\n\n- 列表第一条\n- 列表第二条",
  "shots": [
    { "img": "assets/img/wuming-2.jpg", "alt": "这张图展示了什么" }
  ]
}
```

`category` 只能填这五个之一：

| 填 | 卡片上显示 |
|---|---|
| `shader` | 光影 |
| `map` | 地图 |
| `skin` | 皮肤 |
| `tex` | 材质 |
| `addon` | Addon |

### 3.4 改 / 发一个作品专题页

专题页（`work-rich.html?id=...`）的排版是**代码固定**的：顶图、右上目录、一节一个白底标题条、底部下载区。
作者只能在网页后台改**文字与图片**，增删分节、拖动顺序，样式不会变。

#### A. 用网页后台改（推荐给作者本人）

1. 打开 <https://app.pagescms.org> → 左边点「专题页」
2. 展开要改的那件（目前有：无人区跑酷、仿真工艺系列材质）
3. 表单是**平的**，没有嵌套列表，每一栏都能直接打字：
   - 顶图、作品名、类型行、英文装饰字、副标题、作者
   - **作品信息**：一行一项，写「项目 | 内容」
   - **正文**：一整个写在一栏里，用 `## 标题` 分节
   - **按钮**：一行一个，写「挂在哪节 | 分组 | 按钮文字 | 网址」
4. 保存 → 约 1 分钟上线

**作品信息怎么写**：

```
版本 | V14.FN
关卡数 | 56
平台 | 基岩版 / Java 版
```

**正文怎么写**（`## ` 开头的行就是新的一节，会自动编号并进右上目录）：

```markdown
开头这几段是导语。

## 前言

这一节的内容。空行分段；- 开头是列表；![](assets/img/xxx.jpg) 插图。

## 版本要求

再一节的内容。
```

**按钮怎么写**（四段用竖线隔开，第一段留空就放到页面最底部的「下载与链接」）：

```
下载 |  | 百度网盘 | https://pan.baidu.com/xxxx
下载 | 作者主页 | B 站 | https://space.bilibili.com/xxxx
 | 网易版（中国版） | 四合一 | https://resource-minecraft.h5.163.com/xxxx
```

**排版规矩（改了也不会破版，但请守）**：一节只讲一件事；小节标题四到八个字；图片宽 1200 左右、单张 500KB 以内、文件名英文小写加短横线。

> 梦海旅者（mengsea.html）与创想之都（city.html 及其子页）是独立小站，不在这套模板里，
> 仍是各自页面，见下面的模板说明。

#### B. 新做一个专题页（套无人区跑酷的模板）

**专题页**是那种「像小网站一样」的作品页：顶部一张大图、下面自动生成目录、
一节一节往下排、图片点开能放大。无人区跑酷、仿真工艺系列材质都是这种。

专题页**不用新建文件**，改 `assets/js/site.js` 两处就行：

| 改哪里 | 加什么 | 效果 |
|---|---|---|
| `SHOWCASE_HOME` | 一条横幅 | 作品页「系列作品专题页」里出现一条大横幅 |
| `WORKS` | 一整份正文 | 点进去的那一页 |

#### 第一步：加一条横幅（列表用）

搜 `var SHOWCASE_HOME = [`，在里面加：

```js
{
  id: 'mymap',                            // 小写英文编号，下面 WORKS 要用同一个
  href: 'work-rich.html?id=mymap',        // 固定这样写，把 mymap 换成你的编号
  img: 'assets/img/mymap-cover.jpg',      // 横幅左边那张小封面
  title: '我的地图',                       // 中文名
  en: 'MY MAP NAME',                      // 英文名，横幅上那行描边字
  meta: '作者：某某',                      // 写真人名
  category: 'map',                        // 地图 / 材质 / 光影 / 皮肤 / Addon，见 3.3 的表
  desc: '一句话介绍这是什么'
},
```

#### 第二步：加正文（详情页用）

搜 `var WORKS = {`，加一整块。**左边的名字必须和上面的 `id` 一样**：

```js
'mymap': {
  name: '我的地图',
  displayEn: 'MY MAP|NAME',          // 顶图那行超大英文，用 | 手动分两行
  author: '某某',
  type: '地图 / Map',                 // 显示在左上角的小标签
  tagline: '一句话定位，显示在标题下面',
  cover: 'assets/img/mymap-cover.jpg',
  coverAlt: '封面图里画了什么',

  // ↓ 想让下载按钮出现在正文最上面，就打开这一对
  linksTop: true,
  links: [
    {
      title: '下载',
      solid: true,                    // 实心黑底按钮（不写就是描边按钮）
      items: [
        { label: '百度网盘', href: 'https://...' },
        { label: '蓝奏云', href: 'https://...' }
      ]
    }
  ],

  // ↓ 右侧「作品信息」那一栏，想写几行写几行
  facts: [
    { k: '作品名', v: '我的地图' },
    { k: '作者', v: '某某' },
    { k: '类型', v: '地图 / 跑酷' },
    { k: '平台', v: 'Minecraft 基岩版' }
  ],

  // ↓ 正文，从上往下排
  intro: [
    '第一段直接写，不用加符号。',

    { heading: '玩法' },              // 加一个小标题 → 自动变成「— 01 玩法」并进目录
    '小标题下面的正文。',

    { imgs: [                          // 两张图并排，点开能放大
      { img: 'assets/img/mymap-1.jpg', alt: '这张图展示了什么' },
      { img: 'assets/img/mymap-2.jpg', alt: '这张图展示了什么' }
    ] },

    { heading: '版本要求' },
    '基岩版支持 1.18.30 及以上。',

    { list: [                          // 圆点列表
      '关卡数：56 关',
      '难度：较难',
      '游玩时长：2 小时以上'
    ] },

    { heading: '下载' },
    { links: [                         // 正文中间的按钮组（也可以放这里）
      { solid: true, items: [
        { label: '百度网盘', href: 'https://...' }
      ] }
    ] }
  ]
},
```

#### 正文能用的六种写法

| 写法 | 出来是什么 |
|---|---|
| `'一段文字'` | 一个段落 |
| `{ heading: '小标题' }` | 带编号的节标题，同时自动进目录 |
| `{ list: ['一', '二'] }` | 圆点列表 |
| `{ imgs: [{ img, alt }, ...] }` | 图片网格，点开放大（两张并排最好看） |
| `{ img: '路径', alt: '说明' }` | 一张通栏大图 |
| `{ links: [...] }` | 按钮组 |
| `{ blockquote: '一段话' }` | 引用块 |

#### 目录和编号是自动生成的

- 每写一个 `{ heading: '...' }`，正文里就会多一节「— 01 标题」，页面顶部的目录条自动加一项
- 点击目录能跳转，滚动时还会高亮
- 「作品信息」固定是 00，下载按钮那一节的编号接在正文后面（比如正文 5 节，它就是 06）
- **编号不用手写**，改标题顺序也不会乱

#### 顶图那行英文怎么分行

`displayEn` 里用 `|` 手动断行：

```js
displayEn: 'SEADREAM|VOYAGER'    // 显示成两行，第二行是描边的
displayEn: 'URANSCH PARKOUR'     // 不加 | 就按空格分成两行
```

#### 图片怎么准备

- 封面（`cover`、横幅的 `img`）：宽 1200 像素左右，**600KB 以内**
- 正文里的图：宽 1200 像素左右，**500KB 以内**
- 全部放 `assets/img/`，文件名英文小写加短横线：`mymap-cover.jpg`、`mymap-1.jpg`
- 图片会被按原比例完整显示，不裁切，所以别把边缘重要的内容留得太贴边

#### 第三步：预览、发布

终端里跑 `node tools/serve.mjs 8099`，然后：

- 列表：`http://127.0.0.1:8099/works.html` → 「系列作品专题页」标签
- 详情：`http://127.0.0.1:8099/work-rich.html?id=mymap`（换成你的编号）

看到横幅和正文都对，再跑自检、发布（第四、六节）。

#### 出现这些情况怎么办

| 现象 | 原因 |
|---|---|
| 横幅点进去是别人的作品 | `WORKS` 里的名字和 `id` 不一致 |
| 横幅没出现 | 加到了 `SHOWCASE_HOME` 数组外面，或少个逗号 |
| 目录里没有某一节 | 那一节没写 `{ heading: '...' }` |
| 标题显示的英文分不了行 | `displayEn` 里忘了加 `|` 或空格 |
| 图片破图 | 路径写错、文件名大小写不一致，或没放进 `assets/img/` |
| 页面白屏 | 少逗号、少引号，按 F12 看 Console 红字 |

### 3.7 看访问量

页脚右下角会显示「访问 N 次 / 访客 N 人」，来自**不蒜子**（免费、不用注册），
按域名统计，上线后自动开始累计。

开关在 `assets/js/site.js` 顶部的 `SITE_CONFIG`：

```js
analytics: {
  busuanzi: true,   // 页脚显示访问量；改成 false 就不加载、也不发请求
  baiduId: ''       // 填百度统计的站点 ID，就同时上报一份到百度统计后台
},
```

- 只想看页脚那个数字：保持 `busuanzi: true`

```bash
git checkout -- 文件名
```

## 十、进阶（会的人看）

### 本地预览与自检脚本

```bash
node tools/serve.mjs 8099          # 本地预览（要一直开着）
node tools/check.mjs               # 文件、链接、id、语法、CSS、主题变量
node tools/verify-structure.mjs    # 页面结构是否完整（页眉、侧栏、分区）
node tools/browser-test.mjs        # 真浏览器行为测试（需先起 serve.mjs）
```

这些脚本不需要装依赖，装了 Node 就能跑。

### 改配色

全部颜色在 `assets/css/theme.css`，分四段：默认浅色、系统深色、手动浅色、手动深色。
改强调色要**四段一起改**，`check.mjs` 会检查有没有漏。

### 加一个新工具页

1. 复制 `tools-image.html` 另存为 `tools-new.html`
2. 改标题、说明和页面主体
3. 工具逻辑单独放到 `assets/js/你的名字.js`
4. 在 `tools.html` 里加一张卡片指过去

### 可视化编辑（Pages CMS）

仓库根目录的 `.pages.yml` 是 Pages CMS 的配置：它把 `content/announcements.json` 和
`content/works.json` 描述成表单。访客打开官网时不会加载它，也不会因此产生任何外部请求。

想调整表单字段（比如多一个「副标题」），改 `.pages.yml` 里对应栏目的 `fields` 即可；
同时记得在 `assets/js/site.js` 里读这个新字段，否则填了也不会显示。

### 技术说明

- 纯静态站点：HTML + CSS + 原生 JS，**没有框架、没有构建步骤**
- 主题记忆：访客手动切过深浅色会存在浏览器里，没切过就跟随系统
- 视频工具：浏览器里没有直接转码接口，是「边播边录」实现，耗时约等于视频时长
- 第三方库都在 `assets/vendor/` 自托管，不依赖外部 CDN：
  `mp4box.js`（读视频编码）、`qrcode.js`（分享菜单里的二维码，MIT，只在点开二维码时才加载）

### 域名与 HTTPS（备查，平时不动）

- GitHub Pages 托管，分支 `main`，自定义域名靠仓库里的 `CNAME` 文件
- 根域名用 4 条 A 记录指向 GitHub，`www` 用 CNAME 指向 `porgont.github.io`
- HTTPS 由 GitHub 自动签发续期；**不要动 MX 和 SPF 记录**，会影响邮箱
