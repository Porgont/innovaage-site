# 创想时代开发组 · 官网

这是官网的源代码。改完文件推送到 GitHub，网站 1～2 分钟后自动更新。

- 线上地址：**https://innovaage.cn/**
- 代码仓库：https://github.com/Porgont/innovaage-site

> 这份文档给所有要改网站的人看。**不懂代码也能照着做**，
> 最常用的三种活（改文字、发公告、加作品）都写了完整例子，照抄改字就行。

---

## 一、先弄明白三件事

**第一件：网站就是一堆文件。**
每个页面是一个 `.html` 文件，图片放在 `assets/img/` 里，文字和作品信息大部分存在
`assets/js/site.js` 里。改网站就是改这些文件，跟改 Word 文档没本质区别。

**第二件：改完要「推」上去。**
你在自己电脑上改的是副本（叫本地），改完推一下，GitHub 上那份才更新，网站才跟着变。
不推，谁也看不到。

**第三件：改坏了能退回来。**
每次推之前，Git 都会存一个快照。真改坏了，退回到上一个快照就行，不会丢东西。

## 二、第一次准备（只做一次）

需要三个软件，都是免费的：

| 软件 | 干什么用 | 下载 |
|---|---|---|
| **VS Code** | 打开和编辑文件，还能看效果 | https://code.visualstudio.com/ |
| **Git** | 把改动推上去 | https://git-scm.com/download/win |
| **Node.js** | 跑「本地预览」和「自检」这两类小工具 | https://nodejs.org/ （选 LTS 版） |

装的时候一路点「下一步」就行，不用改选项。

> 完全没碰过这些软件的话，**找技术部帮你装一次、把仓库拉下来一次**，之后你就能自己改文字了。

### 把仓库拉到电脑上

1. 在你想放项目的地方新建文件夹，比如 `D:\网站`
2. 在该文件夹里右键 →「在终端中打开」（或者在地址栏输入 `cmd` 回车）
3. 粘贴下面这行，回车，等它跑完：

```bash
git clone https://github.com/Porgont/innovaage-site.git
```

4. 会多出一个 `innovaage-site` 文件夹，这就是项目
5. 用 VS Code 打开它：VS Code 菜单「文件 → 打开文件夹」，选这个文件夹

### 看一眼本地效果

1. VS Code 菜单「终端 → 新建终端」
2. 输入：

```bash
node tools/serve.mjs 8099
```

3. 浏览器地址栏输入 `http://127.0.0.1:8099` 回车

本地看到的和线上的长得一样。这个终端窗口别关，关了本地预览就停了。
改完文件保存，回到浏览器按 F5 刷新就能看到新内容。

## 三、最常见的七件事（挑你要做的看）

### 3.1 改一段已有的文字

比如想把「关于我们」里那句下载量改掉。

1. VS Code 里按 `Ctrl + P`，输入 `about.html`，回车打开
2. 按 `Ctrl + F` 搜索你想改的原句，比如 `五千万`
3. 直接改这几个字，改完按 `Ctrl + S` 保存
4. 浏览器刷新看效果
5. 按第四节的步骤推上去

**只改文字是可以放心的**：不要动尖括号 `< >` 里面的东西，那就是排版标记。
把它们想成「格式开关」，删了页面就乱。

```
改前：<p>在我的世界中国版总下载量已超过五千万。</p>
改后：<p>在我的世界中国版总下载量已超过六千万。</p>
      ↑ 这些尖括号里的内容别动，只改中间的中文
```

### 3.2 发一条公告（完整例子，照抄）

**只改一个文件**：`assets/js/site.js`。

#### 第一步：找到公告列表

`Ctrl + P` 打开 `assets/js/site.js`，按 `Ctrl + F` 搜 `ANNOUNCEMENTS`，
会看到一堆用 `{ }` 包起来的条目。**新公告放在最前面。**

#### 第二步：整条复制一份

从 `{` 到 `},` 完整复制，粘到 `[` 后面，再改里面的内容。
下面这条可以直接抄，把中文换成你要写的：

```js
{
  id: 'new-2027-01',
  date: '2027-01-20',
  title: '新年第一波材质包上架',
  color: 'gold',
  tags: ['版本发布'],
  body: `
第一句先写清楚这是什么，因为它会显示在公告列表上。

## 小标题这样写

正文直接写就行，一段一行，**想加粗用两个星号**。

- 列表第一条
- 列表第二条

要放链接：[点这里看详情](https://example.com)
`
},
```

#### 第三步：每一项填什么

| 写什么 | 意思 | 例子 |
|---|---|---|
| `id` | 网址里用的编号，**小写英文、数字、短横线**，不能重复 | `'new-2027-01'` |
| `date` | 日期，固定「年-月-日」，**月日不足两位补 0** | `'2027-01-20'` |
| `title` | 标题，一句话 | `'新年第一波材质包上架'` |
| `color` | 左边那根色条，四选一 | `'green'` `'gold'` `'diamond'` `'redstone'` |
| `pin` | 想置顶就写 `pin: true,`，不想就整行删掉 | — |
| `tags` | 标签，决定筛选按钮能不能筛到它 | `['招募']` `['版本发布']` `['合作']` |
| `body` | 正文，用下面这套写法 | 见上例 |

#### 第四步：正文怎么写

正文用的是 **Markdown**，就是打字时多加几个符号：

| 想做什么 | 怎么写 | 效果 |
|---|---|---|
| 分段 | 中间空一行 | 两段分开 |
| 加粗 | `**这几个字**` | **这几个字** |
| 小标题 | `## 标题文字` | 大一号的标题 |
| 列表 | 每行开头写 `-` 加空格 | • 一条 |
| 放链接 | `[显示的字](网址)` | 显示的字可点 |
| 放图片 | `![图里画了什么](assets/img/xx.jpg)` | 图片 |

**注意**：整段正文要用一对反引号包起来（键盘左上角、Esc 下面那个键），
开头一个、结尾一个，像上面例子那样。别用单引号。

#### 第五步：放图片

1. 图片丢进 `assets/img/` 文件夹
2. 文件名用**英文小写加短横线**：`news-2027-banner.jpg` ✔ ／ `公告图 1.png` ✘
3. 宽度 1200 像素够用，**单张压到 500KB 以内**（用站内 [图片处理工具](https://innovaage.cn/tools-image.html) 压）
4. 正文里这样写：`![新年活动海报](assets/img/news-2027-banner.jpg)`

#### 第六步：跑一下小工具

在项目文件夹的终端里依次跑：

```bash
node tools/build-feed.mjs    # 更新 RSS 订阅文件，不加这步订阅者看不到
node tools/subset-font.mjs   # 把这次新出现的字补进字体文件
node tools/check.mjs         # 自检，最后一行要是「全部检查通过」
```

三条都跑完再发布。第一条会显示生成了几条，第二条会显示子集字数量，第三条看最后一行。

#### 第七步：发布

见第四节，就三条命令。

#### 出现这些情况怎么办

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 整页白屏、公告不出来 | 少了个逗号 `,`，或反引号没成对 | 按 F12 看 Console 红字，按提示找那一行 |
| 列表上日期显示成 01/2 | `date` 里月日没补 0 | 改成 `'2027-01-02'` |
| 点进公告说「没找到」 | `id` 重复了 | 换个没用过的编号 |
| 筛选按不到它 | `tags` 里没写对应标签 | 补上 `'版本发布'` 这类 |
| 图片是破图 | 路径写错，或没放进 `assets/img/` | 对照文件名逐个字母检查 |

> 公告列表**只显示标题和正文开头约 96 个字**，所以正文第一句要直接说清是什么事，
> 别一上来写「今天要说几件事」。

### 3.3 加一件代表作品

也是只改 `assets/js/site.js`，要加**两处**：列表卡片一份、详情页一份。

#### 第一步：准备图

- 图放进 `assets/img/`，名字用英文小写加短横线：`wuming-1.jpg`
- 封面宽 1200 像素够用，**单张 600KB 以内**
- 有多张截图就依次叫 `wuming-1.jpg`、`wuming-2.jpg`……

#### 第二步：加列表卡片

搜 `var SHOWCASE = [`，在里面加一段：

```js
{
  id: 'wuming',                          // 小写英文编号，等下详情页要用同一个
  img: 'assets/img/wuming-1.jpg',        // 列表里显示的封面
  title: '无名',                          // 作品名
  meta: '作者：某某',                     // 写真人名，不要写开发组
  category: 'shader',                    // 类型，见下表
  desc: '一句话说明这是什么。'            // 卡片上那句简介
},
```

`category` 只能填这五个之一：

| 填 | 卡片上显示 |
|---|---|
| `shader` | 光影 |
| `map` | 地图 |
| `skin` | 皮肤 |
| `tex` | 材质 |
| `addon` | Addon |

#### 第三步：加详情页

搜 `var WORKS = {`，加一段。**左边的名字必须和上面的 `id` 一模一样**：

```js
'wuming': {
  name: '无名',
  author: '某某',
  type: '光影 / Shader',
  tagline: '一句话定位，显示在标题下面',
  cover: 'assets/img/wuming-1.jpg',
  coverAlt: '封面图里画了什么',
  facts: [
    { k: '作品名', v: '无名' },
    { k: '作者', v: '某某' },
    { k: '类型', v: '光影 / Shader' },
    { k: '平台', v: 'Minecraft 基岩版' }
  ],
  intro: [
    '第一段介绍。',
    '第二段介绍。'
  ],
  shots: [
    { img: 'assets/img/wuming-2.jpg', alt: '这张图展示了什么' }
  ]
},
```

要点：

- `facts` 是右侧信息栏，想写几行写几行；**不确定的信息别写**（比如不确定是基岩版还是 Java，就别填「平台」）
- `intro` 里一个字符串一段
- `shots` 只写 `img` 和 `alt`，不写说明文字
- 想放下载按钮，别在正文写链接，用 `links` 字段（见下面）

```js
links: [
  {
    title: '网易版',
    items: [
      { label: '四合一', href: 'https://...' },
      { label: '普通版 128x', href: 'https://...' }
    ]
  }
]
```

#### 第四步：预览、发布

终端跑 `node tools/serve.mjs 8099`，浏览器打开
`http://127.0.0.1:8099/works.html`，能看到卡片、点进去能看到详情页，就说明对了。

然后跑自检、发布（第四节）。

#### 出现这些情况怎么办

| 现象 | 原因 |
|---|---|
| 卡片没出现 | 少了逗号，或者加到了数组外面 |
| 点进去是别人的作品 | `WORKS` 里的名字和 `SHOWCASE` 的 `id` 对不上 |
| 卡片上没有「查看详情」 | `SHOWCASE` 那条忘了写 `id` |
| 同一件作品出现两次 | 在 `SHOWCASE` 里写了两条，应该合成一条 |

### 3.4 发一个作品专题页（套无人区跑酷的模板）

**专题页**是那种「像小网站一样」的作品页：顶部一张大图、下面自动生成目录、
一节一节往下排、图片点开能放大。无人区跑酷、仿真工艺系列材质都是这种。

专题页**不用新建文件**，改 `assets/js/site.js` 两处就行：

| 改哪里 | 加什么 | 效果 |
|---|---|---|
| `SHOWCASE_HOME` | 一条横幅 | 作品页「系列作品专题页」里出现一条大横幅 |
| `WORKS` | 一整份正文 | 点进去的那一页 |

#### 第一步：加一条横幅（列表用）

搜 `var SHOWCASE_HOME = [`，在里面加：

```js
{
  id: 'mymap',                            // 小写英文编号，下面 WORKS 要用同一个
  href: 'work-rich.html?id=mymap',        // 固定这样写，把 mymap 换成你的编号
  img: 'assets/img/mymap-cover.jpg',      // 横幅左边那张小封面
  title: '我的地图',                       // 中文名
  en: 'MY MAP NAME',                      // 英文名，横幅上那行描边字
  meta: '作者：某某',                      // 写真人名
  category: 'map',                        // 地图 / 材质 / 光影 / 皮肤 / Addon，见 3.3 的表
  desc: '一句话介绍这是什么'
},
```

#### 第二步：加正文（详情页用）

搜 `var WORKS = {`，加一整块。**左边的名字必须和上面的 `id` 一样**：

```js
'mymap': {
  name: '我的地图',
  displayEn: 'MY MAP|NAME',          // 顶图那行超大英文，用 | 手动分两行
  author: '某某',
  type: '地图 / Map',                 // 显示在左上角的小标签
  tagline: '一句话定位，显示在标题下面',
  cover: 'assets/img/mymap-cover.jpg',
  coverAlt: '封面图里画了什么',

  // ↓ 想让下载按钮出现在正文最上面，就打开这一对
  linksTop: true,
  links: [
    {
      title: '下载',
      solid: true,                    // 实心黑底按钮（不写就是描边按钮）
      items: [
        { label: '百度网盘', href: 'https://...' },
        { label: '蓝奏云', href: 'https://...' }
      ]
    }
  ],

  // ↓ 右侧「作品信息」那一栏，想写几行写几行
  facts: [
    { k: '作品名', v: '我的地图' },
    { k: '作者', v: '某某' },
    { k: '类型', v: '地图 / 跑酷' },
    { k: '平台', v: 'Minecraft 基岩版' }
  ],

  // ↓ 正文，从上往下排
  intro: [
    '第一段直接写，不用加符号。',

    { heading: '玩法' },              // 加一个小标题 → 自动变成「— 01 玩法」并进目录
    '小标题下面的正文。',

    { imgs: [                          // 两张图并排，点开能放大
      { img: 'assets/img/mymap-1.jpg', alt: '这张图展示了什么' },
      { img: 'assets/img/mymap-2.jpg', alt: '这张图展示了什么' }
    ] },

    { heading: '版本要求' },
    '基岩版支持 1.18.30 及以上。',

    { list: [                          // 圆点列表
      '关卡数：56 关',
      '难度：较难',
      '游玩时长：2 小时以上'
    ] },

    { heading: '下载' },
    { links: [                         // 正文中间的按钮组（也可以放这里）
      { solid: true, items: [
        { label: '百度网盘', href: 'https://...' }
      ] }
    ] }
  ]
},
```

#### 正文能用的六种写法

| 写法 | 出来是什么 |
|---|---|
| `'一段文字'` | 一个段落 |
| `{ heading: '小标题' }` | 带编号的节标题，同时自动进目录 |
| `{ list: ['一', '二'] }` | 圆点列表 |
| `{ imgs: [{ img, alt }, ...] }` | 图片网格，点开放大（两张并排最好看） |
| `{ img: '路径', alt: '说明' }` | 一张通栏大图 |
| `{ links: [...] }` | 按钮组 |
| `{ blockquote: '一段话' }` | 引用块 |

#### 目录和编号是自动生成的

- 每写一个 `{ heading: '...' }`，正文里就会多一节「— 01 标题」，页面顶部的目录条自动加一项
- 点击目录能跳转，滚动时还会高亮
- 「作品信息」固定是 00，下载按钮那一节的编号接在正文后面（比如正文 5 节，它就是 06）
- **编号不用手写**，改标题顺序也不会乱

#### 顶图那行英文怎么分行

`displayEn` 里用 `|` 手动断行：

```js
displayEn: 'SEADREAM|VOYAGER'    // 显示成两行，第二行是描边的
displayEn: 'URANSCH PARKOUR'     // 不加 | 就按空格分成两行
```

#### 图片怎么准备

- 封面（`cover`、横幅的 `img`）：宽 1200 像素左右，**600KB 以内**
- 正文里的图：宽 1200 像素左右，**500KB 以内**
- 全部放 `assets/img/`，文件名英文小写加短横线：`mymap-cover.jpg`、`mymap-1.jpg`
- 图片会被按原比例完整显示，不裁切，所以别把边缘重要的内容留得太贴边

#### 第三步：预览、发布

终端里跑 `node tools/serve.mjs 8099`，然后：

- 列表：`http://127.0.0.1:8099/works.html` → 「系列作品专题页」标签
- 详情：`http://127.0.0.1:8099/work-rich.html?id=mymap`（换成你的编号）

看到横幅和正文都对，再跑自检、发布（第四、六节）。

#### 出现这些情况怎么办

| 现象 | 原因 |
|---|---|
| 横幅点进去是别人的作品 | `WORKS` 里的名字和 `id` 不一致 |
| 横幅没出现 | 加到了 `SHOWCASE_HOME` 数组外面，或少个逗号 |
| 目录里没有某一节 | 那一节没写 `{ heading: '...' }` |
| 标题显示的英文分不了行 | `displayEn` 里忘了加 `|` 或空格 |
| 图片破图 | 路径写错、文件名大小写不一致，或没放进 `assets/img/` |
| 页面白屏 | 少逗号、少引号，按 F12 看 Console 红字 |

### 3.5 换图 / 加截图

1. 新图放进 `assets/img/`
2. 文件名英文小写加短横线，**单张 500KB 以内**
3. 如果用 `site.js` 里的作品数据，就把那张的路径改成新文件名
4. 如果是页面正文里的图，按 3.1 的方法找到那行改路径

MC 截图动辄 2～5MB，**一定要先压**。用站内 [图片处理工具](https://innovaage.cn/tools-image.html)，
选个预设就行；只想转格式、不改尺寸就选「无限制」。

### 3.6 改群号 / 问卷链接

只在 `assets/js/site.js` 顶部一处，全站（页脚、联系我们、关于我们）一起变：

```js
var SITE_CONFIG = {
  surveyUrl: 'https://www.wjx.cn/vm/xxxx.aspx',  // 报名问卷
  qqAudit:   '1045216325',   // 对外审核群
  qqPublic:  '788233856',    // 对外交流群
  qqCouncil: '1018260006',   // 开发理事会（对外代投）
  ...
};
```

**留空就是隐藏**。比如邮箱不知道就先留 `email: ''`，页面上这一行自动消失，不会出现空白。

### 3.7 看访问量

页脚右下角会显示「访问 N 次 / 访客 N 人」，来自**不蒜子**（免费、不用注册），
按域名统计，上线后自动开始累计。

开关在 `assets/js/site.js` 顶部的 `SITE_CONFIG`：

```js
analytics: {
  busuanzi: true,   // 页脚显示访问量；改成 false 就不加载、也不发请求
  baiduId: ''       // 填百度统计的站点 ID，就同时上报一份到百度统计后台
},
```

- 只想看页脚那个数字：保持 `busuanzi: true`
- 还想要**详细报表**（每天多少人、从哪来、看哪个页面、手机还是电脑）：
  去 https://tongji.baidu.com/ 注册 → 添加网站 `innovaage.cn` → 复制它给的 ID
  （一串字母数字）填进 `baiduId`，之后在百度统计后台看

## 四、发布（三条命令）

0. 推之前先拉一次，避免覆盖别人的改动：

```bash
git pull
```

1. 提交你的改动：

```bash
git add -A
git commit -m "新增公告：新年第一波材质包上架"
```

`-m` 后面那句话写清你干了什么，以后回头查就靠它。

2. 推上去：

```bash
git push
```

3. 等 1～2 分钟，打开 https://innovaage.cn/ 刷新看效果。

**推不上去的常见原因**：

| 提示 | 怎么办 |
|---|---|
| `Could not connect to server` / `proxy` | 代理软件没开，打开它再推 |
| 要求登录 / `Authentication failed` | GitHub 要登录，按提示用浏览器授权一次 |
| `rejected` / `non-fast-forward` | 别人刚推过，先 `git pull` 再试 |

## 五、改坏了怎么办

**还没推上去**（只是本地改坏了）：把那个文件还原成上次的样子

```bash
git checkout -- 文件名
```

比如 `git checkout -- assets/js/site.js`。

**已经推上去了**：在 GitHub 网页上打开那次提交，点「Revert」，
或者本地 `git revert 提交编号`，它会生成一次反向提交。

**完全不会操作**：把终端里的报错截图发给技术部，别自己乱试。
回退很容易，着急的是别在坏的状态上继续改。

## 七、内容规矩

这几条是踩过坑总结的，请一起守着：

1. **不要编内容。** 不确定的作者名、版本号、下载链接、授权条款，宁可不写或留空，
   也不要写一个看起来合理但其实是错的。
2. **作品图必须真能加载。** 自检里会检查每张图有没有真正读到。
3. **一个作品只占一条。** 多张图放进详情页，不要在列表里重复列。
4. **作者写真人。** 团队只能出现在「移植 / 维护」这类角色里。
5. **投稿规格写死的地方别改。** 视频工具里「符合投稿规范」那一档是投稿方的要求。
6. **第三方作品要署名。** 例如 matoga 的作者是芝世，来源要保留。
7. **站内不要放本站源码的链接。** 仓库地址不写进任何页面。

## 十、进阶（会的人看）

### 本地预览与自检脚本

```bash
node tools/serve.mjs 8099          # 本地预览（要一直开着）
node tools/check.mjs               # 文件、链接、id、语法、CSS、主题变量
node tools/verify-structure.mjs    # 页面结构是否完整（页眉、侧栏、分区）
node tools/browser-test.mjs        # 真浏览器行为测试（需先起 serve.mjs）
```

这些脚本不需要装依赖，装了 Node 就能跑。

### 改配色

全部颜色在 `assets/css/theme.css`，分四段：默认浅色、系统深色、手动浅色、手动深色。
改强调色要**四段一起改**，`check.mjs` 会检查有没有漏。

### 加一个新工具页

1. 复制 `tools-image.html` 另存为 `tools-new.html`
2. 改标题、说明和页面主体
3. 工具逻辑单独放到 `assets/js/你的名字.js`
4. 在 `tools.html` 里加一张卡片指过去

### 技术说明

- 纯静态站点：HTML + CSS + 原生 JS，**没有框架、没有构建步骤**
- 主题记忆：访客手动切过深浅色会存在浏览器里，没切过就跟随系统
- 视频工具：浏览器里没有直接转码接口，是「边播边录」实现，耗时约等于视频时长
- 第三方库都在 `assets/vendor/` 自托管，不依赖外部 CDN：
  `mp4box.js`（读视频编码）、`qrcode.js`（分享菜单里的二维码，MIT，只在点开二维码时才加载）

### 域名与 HTTPS（备查，平时不动）

- GitHub Pages 托管，分支 `main`，自定义域名靠仓库里的 `CNAME` 文件
- 根域名用 4 条 A 记录指向 GitHub，`www` 用 CNAME 指向 `porgont.github.io`
- HTTPS 由 GitHub 自动签发续期；**不要动 MX 和 SPF 记录**，会影响邮箱
